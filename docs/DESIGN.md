# plugin_discovery implementation notes

**English** | [中文](DESIGN.zh-CN.md)

How the **current code** works. Design rationale: [`CROSS_PLATFORM_DESIGN.md`](CROSS_PLATFORM_DESIGN.md); API reference: [`LIBRARY.md`](LIBRARY.md). Behaviour marked "provisional" corresponds to questions left to detailed design (listed in section 2 of `OPEN_QUESTIONS.md` in plugin-discovery-design-note) and may change.

Goal: without ROS (no colcon / ament / pluginlib / class_loader), decide from configuration which backends to load. Each backend reports, through its own vendor SDK, the devices it can use on this machine. Used by several **independent** domains such as camera / imu / audio / lidar: each domain has its own interface and its own set of backends.

## 1. Layers and components

| Layer | Component | Responsibility | Counterpart |
|---|---|---|---|
| L4 application | Apps (customer applications and middleware; ROS nodes) | call the domain interface and use devices; **know nothing about SoCs, do no device probing** | — |
| L3 management | `libplugin_discovery.so`: `PluginRegistry`, `BackendSet<T>`, `PluginHandle<T>`, `PluginInfo`, `Skipped`, the `Backend` base and macros | read manifests and configuration, decide which backends load, check interface version and ABI, call `probe()`, collect devices | pluginlib |
| L2 loading | `libplugin_loader.so`: `ClassLoader`, `MultiLibraryClassLoader`, the global factory table, exceptions | dlopen / dlclose, registration macro, factory table, reference counting, managed / unmanaged instances | class_loader |
| L1 plugins | one `.so` per backend (`PLUGIN_DISCOVERY_REGISTER_BACKEND(Derived, Interface)`) plus its private vendor libraries | implement the domain interface; `probe()` asks their vendor SDK | — |

Roles on the side:

- **Domain interface**: an abstract class deriving from `plugin_discovery::Backend`, declaring its domain and version with `PLUGIN_DISCOVERY_INTERFACE(Interface, "domain", major, minor)`. Apps and backends depend on it; apps depend on no backend.
- **Manifest** (`*.plugin.yaml`): one per backend, describing name, class, interface, library path, domain, backend name, origin, priority and capabilities. Generated by CMake, installed to `share/<domain>/plugins/`.
- **Configuration** (`*.config.yaml`): decides which backends each domain loads. Three sources:
  - platform configuration, in `/etc/plugin_discovery/platform.d/`: links to the candidate files that platform packages install in `share/plugin_discovery/platforms.d/` (the library never reads the candidates). The `platform-detect` executable, run once on the first boot by a systemd oneshot unit, picks the candidates that match the machine and the OS type;
  - customer configuration, in `/etc/plugin_discovery/config.d/`;
  - a manual choice.

  Platform-tier files apply first and customer-tier files after, in ascending file-name order within a tier, the last one winning. Every file takes part; a customer overrides only with `reset` and `disable`.

Dependencies:

```
App ──> domain interface <── backend .so ──> vendor SDK
App ──> libplugin_discovery.so ──> libplugin_loader.so <── backend .so
backend .so ──> libplugin_discovery.so      (the registration macro writes its version record here)
libplugin_discovery.so ──reads──> *.plugin.yaml, platform.d/*.config.yaml, config.d/*.config.yaml
```

Apps and backends must link **the same** `libplugin_loader.so` and `libplugin_discovery.so`.

## 2. Key types

- `Backend`: base of every backend, with one virtual function, `ProbeResult probe()`. The default returns `ok` with one device whose id is `default`.
- `ProbeResult { status, devices, message }`: `status` is `Ok` / `Unsupported` / `Fault`; `DeviceInfo { id, node, description }`.
- `PluginRegistry`
  - `scan()`: reads every manifest and configuration file, loads no `.so`
  - `plan(base, domain, manual, caps)`: only computes which backends would load, returns a `LoadPlan`
  - `load<T>(manual, caps)`: `create`, `probe` and de-duplicate devices in turn, returns a `BackendSet<T>`
  - `create<T>(info | name)`: loads one backend, checking version and ABI first
  - `list()`, `find()`, `all()`
- `BackendSet<T> { backends, skipped, how, first, compat }`:
  - each entry of `backends` is a `LoadedBackend { PluginHandle<T> handle; vector<DeviceInfo> devices; }`;
  - `how` is `manual` / `config` / `all`;
  - `first` is the first entry of the final list (the default backend), loaded or not, installed or not (a configured but missing name is returned as is); `compat` is the domain's compatibility flag (config only).
- `Skipped { name, kind, reason }`: `kind` is one of `not_listed`, `disabled`, `missing`, `lacks_capability`, `incompatible`, `load_failed`, `unsupported`, `fault`, `duplicate_device`.
- `PluginHandle<T>`: holds both the object and its `ClassLoader`; `reset()` and the destructor always destroy the object before releasing the library.

## 3. Build time

1. The interface header uses `PLUGIN_DISCOVERY_INTERFACE`.
2. A backend `.cpp` uses `PLUGIN_DISCOVERY_REGISTER_BACKEND(Derived, Interface)`, which expands to two parts:
   - `PLUGIN_REGISTER_CLASS(Derived, Interface)`: an entry in plugin_loader's factory table;
   - a static object that, when the library is dlopen'd, calls `detail::record_backend(...)` to record in `libplugin_discovery.so` {library path (from `dladdr`), interface name, class name, compile-time major.minor, ABI tag}.
3. CMake calls `plugin_discovery_add_plugin(TARGET … DOMAIN … NAME … CLASS … BASE … [BACKEND] [ORIGIN] [PRIORITY] [CAPABILITIES])`, which does three things:
   - links the target against `plugin_discovery::plugin_discovery`;
   - installs the `.so` to `lib/<domain>/`;
   - generates the manifest with `file(GENERATE)` and installs it to `share/<domain>/plugins/` (separate component `manifests`).

   Passing `PLATFORMS` is a `FATAL_ERROR`.
4. Platform packages install their candidate configuration files to `share/plugin_discovery/platforms.d/` with `plugin_discovery_install_config(<file>...)`. On the first boot `platform-detect` links the candidates that match the machine and the OS type into `/etc/plugin_discovery/platform.d/`.

Install layout:

```
<prefix>/
├── bin/<app>
├── lib/libplugin_loader.so  libplugin_discovery.so
├── lib/<domain>/lib<backend>.so  lib<vendor>.so
├── share/<domain>/plugins/<backend>.plugin.yaml
├── bin/platform-detect
├── share/plugin_discovery/platforms.d/*.config.yaml     (candidates from platform packages; not read by the library)
/etc/plugin_discovery/platform.d/<domain>.config.yaml    (links made by platform-detect)
/etc/plugin_discovery/config.d/*.config.yaml             (customer configuration)
/var/lib/plugin_discovery/platform-detect.done           (stamp file)
```

## 4. Runtime

### 4.1 Deciding which backends load (`PluginRegistry::plan`)

```
pool = plugins whose base is this interface and that have every required capability
       order: customer first → priority descending → name ascending  (only when nothing orders them)

wanted (backend names to load, ordered):
  1. load()'s manual argument                          how=manual
  2. else PLUGIN_DISCOVERY_BACKEND_<DOMAIN>=a,b        how=manual
  3. else configuration: the merged final list (last file wins; a file's backends go to the front), minus disable   how=config; compat flag from the domain's config
  4. none of these → the whole pool, with a WARN saying no platform configuration matched   how=all   (provisional)

for each wanted name: take the pool's plugins with that backend name; none → skipped[missing]
a backend name with both a customer and a qcom plugin → keep only the customer one, the qcom one is skipped[disabled]
plugins not chosen → skipped[not_listed] or skipped[disabled]                       (provisional)
```

### 4.2 Load, probe, collect (`PluginRegistry::load<T>`)

```
App          PluginRegistry           ClassLoader          backend .so          vendor SDK
 │ scan() ──────>│ read manifests, config    │                     │                     │
 │ load<T>() ───>│ plan()                    │                     │                     │
 │               │ for each planned plugin:  │                     │                     │
 │               │  new ClassLoader(path) ──>│ dlopen ────────────>│ static init:         │
 │               │                           │                     │  factory + version record
 │               │  check version / ABI (look up the record)       │                     │
 │               │  createUniqueInstance ───>│ new object          │                     │
 │               │  probe() ─────────────────────────────────────> │ ask the SDK ───────>│
 │               │  <── Ok(devices) / Unsupported / Fault          │                     │
 │               │  drop device nodes an earlier backend already reported                │
 │ <── BackendSet<T> (backends + devices, skipped, how); one summary is printed           │
 │ b.handle->... (use devices)                                                            │
 │ BackendSet destroyed: each handle destroys its object first, then dlclose               │
```

How each outcome is handled:

| Case | Handling |
|---|---|
| library fails to load / class not registered | `skipped[load_failed]`, go on with the next |
| not registered with the new macro, different major, older minor than the app, different ABI tag | `skipped[incompatible]`, no object created; the message names both versions or toolchains |
| `probe()` returns `Unsupported` | unload, `skipped[unsupported]`, INFO |
| `probe()` returns `Fault` or throws | unload, `skipped[fault]`, ERROR; the other backends carry on (the domain's `compat` only affects selection, not this) |
| a reported device node was already reported by an earlier backend | that device is not given to it, `skipped[duplicate_device]`; if that leaves it with no device, it is unloaded (provisional) |

Selection by the caller (e.g. `CameraManager`): no backend named → `first`; if it is not loaded or cannot open the device the call fails. `compat` is read but not acted on for now: there is no fallback. A named backend is used as given.

`load()` never throws because a single backend fails; `create()` throws `PluginError` on failure.

### 4.3 Version and ABI rules (provisional)

- **major**: must be equal. **minor**: the backend's compile-time minor must not be lower than the app's.
- **ABI tag**: `gcc<major>` or `clang<major>`, plus `-cxx11abi<_GLIBCXX_USE_CXX11_ABI>`; both sides must match. Predefining `PLUGIN_DISCOVERY_ABI_TAG` overrides it; the tests use that to fake a mismatch.
- **What is checked**: the record the `.so` registered itself, not the manifest, so manifest and `.so` cannot disagree.
- **Records per library**: records are keyed by the library path from `dladdr`, so the same class name in two libraries is not confused.

## 5. Mapping to class_loader / pluginlib

| Here | Counterpart | Notes |
|---|---|---|
| `plugin_loader` | `class_loader` | aligned interface (class names, methods, exceptions; the registration macro is renamed `PLUGIN_REGISTER_CLASS`); 27 scenarios diff-tested against upstream |
| `plugin_discovery` | `pluginlib` | same role (discovery + creation), different API: loads several backends per configuration, `probe()`, version / ABI checks; no ROS package system |

Incompatibilities:
- not binary compatible: `.so` files built with `PLUGINLIB_EXPORT_CLASS` do not register;
- a backend registered with the plain `PLUGIN_REGISTER_CLASS` macro loads in plugin_loader but is rejected by plugin_discovery because it has no version record;
- Linux only.

## 6. Tests

- `test/run_diff.sh <build>`: plugin_loader's 27 scenarios, 34 checks.
- `test/registry_test <build>/test/backends`: 34 checks, covering:
  - the fallback without configuration;
  - the merged view (`config_view()`) behind `pluginlib-detect`;
  - platform configuration, customer configuration and `disable`;
  - manual choice (argument and environment variable), unknown backend names;
  - capability filtering;
  - a customer backend replacing a qcom backend of the same name;
  - the three probe results;
  - too-old minor, ABI mismatch;
  - de-duplication of a device node;
  - rejection of manifests with a `platforms` field;
  - creation by name;
  - a missing library reported as `load_failed` while the other backends still load.
- The test backends are 8 libraries built from `test/backends/test_backend.cpp` with different definitions.
